# FastAPI Framework Post Mortem

After my horrendous (and hyper negatively-biased) tour on ASP.NET Core, FastAPI is quite the breath of fresh air. So fresh that it feels like breathing in the clean mountain air after living in the crowded carbon filled city air like Kuala Lumpur. It doesn't abstract too much features to the point of confusion and their docs are very well written (and easy on my eyes too). It also has the advantage of being written with Python which I think anyone can pick up easily. Out of all the frameworks I worked on so far, I think FastAPI was the easiest to work with. Scaffolding and setting up the docker container for it was quick and easy, file structure and conventions are left to the dev means I don't need to think to much about how to use the framework, just apply some of the conventions I've learned on the previous frameworks and voila, an API application with five endpoints ready to go in a very short amount of time. I think if I make Python one of my primary languages, the time it takes to set this project could be shortened further (it took me 7 hours-ish to complete this, which is shorter than the other four frameworks I've worked on so far).

So let's talk about FastAPI itself. Just like Gin and unlike Django, FastAPI is a pure backend framework if I may allow to call it that. Very bare bones which I'm surprised I end up liking. Having the freedom to dictate my own conventions and the shape of the project is something I didn't know I appreciate when working with a framework. However, it does have it's drawbacks. Just like Gin, FastAPI does not come feature rich like other frameworks (Laravel, Ruby on Rails, ASP.NET Core). So its either make one from scratch or import a library, so of course I went with the latter. Despite that, it doesn't change the fact that I like FastAPI very much. One thing I need to note if working with FastAPI in the future is to setup a proper dev environment that properly caters to Python, which means using extension to improve code quality and catch bugs before it appears. [If only I can apply Compiler Driven Development like in Rust, I think I should look into extensions that could mimic that behavior].

If you're reading this and you are very familiar with FastAPI, you might be wondering why I haven't yet mention Starlette and Pydantic. Well, that's because I don't understand what are they and their functions. I don't want to give you something Gemini barfs at when searching on Google, so I rather tell you, I don't know (yet). But because of how exciting and easy it is to work with FastAPI, I definitely will do a project involving it in the near future (Gin too, I like Gin).
